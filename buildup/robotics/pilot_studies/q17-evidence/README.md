# Q17 Evidence-to-Action Feasibility Study

Updated: 2026-09-29

## Purpose And Boundary

탐색 목적이다. `check_block_color` 한 과업에서 관찰로 숨은 색을 알아낸 시점, 알맞은 pad를 선택한 시점, 물리적으로 놓은 결과를 실제 source 기록으로 구분할 수 있는지 확인한다. [질문](../../questions/evidence-conditioned-action-selection.md)의 첫 관찰이며 ActiveArena의 성능 재현이나 새 방법 검증이 아니다.

같은 task/초기 상태와 정책·실행 예산에서 정상 입력, 실제 획득 가능한 과거 단서를 보존한 입력, 명시적 oracle target/subtask를 비교하는 것이 목표다. Oracle이 같은 지식을 공유하지 않으면 진단 상한으로만 해석한다. 대상 선택이 이미 맞는 실패와 단서 부족을 섞지 않는다. ID/OOD 전체 평가, 35-task dataset, policy 재학습과 real robot은 이 첫 study에 포함하지 않는다.

## ML First-Target Screen (selected 2026-09-29)

[과업군 재비교](../../../selection.md#q17-task-family-reassessment-2026-09-29)에서 다음 한 사례를 고른다. [공식 ML source](../../../../external/q17-activearena/envs/blocks_ranking_rgb_rotate_view.py)의 첫 subtask는 green 블록 찾기·집기이며 `search_target_keys`/`action_target_keys`가 `B`다. 최종 evaluator는 RGB 순서·간격·열린 gripper를 검사하므로, 첫 집기의 **대상 identity와 물리적 집기**는 별도로 판독한다. 과업 instruction은 색과 순서를 이미 알려 주므로 색 추론 검사가 아니다. 공식 ID `info_gathering_demo` manifest 첫 seed `100000` 하나를 사용한다. 첫 관찰 전 질문은 초기 정책 입력에서는 green이 가려져 있다가 회전 시점 입력에서 보이는지, 그리고 그 뒤 정책이 어느 블록을 첫 집기 대상으로 삼는지다. Source subtask metadata를 정책 입력에 넣지 않는다.

Workspace 전용 기존 simulator·OFT Docker 경로에서 같은 checkpoint로 한 짧은 episode를 실행한다. 입력 PNG, instruction, 첫 집기 전후 블록 위치·gripper 상태와 native outcome을 저장하고 source metadata의 정답 물체와 대조한다. 먼저 입력 가시성을 판독하고, 처음부터 green이 보이면 이 사례를 **능동적 정보 획득의 증거로 사용하지 않는다**. 정책이 회전/집기까지 도달하지 못하면 acquisition/execution 장벽으로 분류한다. 회전 후 처음 보인 green 대신 다른 블록을 집거나 접근하면 같은 상태의 단순 task-text 목표 위치 단서(oracle 진단) 대조를 검토한다. 기존 OFT bridge는 subtask text를 행동 prompt로 쓰지 않으므로 subtask 문장만 바꾸는 대조는 제외한다. Green을 올바르게 집으면 첫 선택의 실패는 없으며 이후 배치 실패를 정보 결합의 증거로 해석하지 않는다. 단일 사례로 실패율·method 효과를 추정하지 않는다.

새 dataset·모델 학습은 필요하지 않다고 예상하지만 이 과업 고유 asset 누락 여부는 실행 전에 Docker mount/source에서 확인한다. 새 asset이 필요하면 종류·크기·검증·비용을 먼저 기록하고 제한된 한 사례의 가치와 비교한다. 실행 명령·output·검증·소유 container/image 정리는 이 owner에 후속 기록한다. 아래 초기 `check_block_color` protocol과 color-count 결과는 앞선 경로의 기록이다.

## First Observation Protocol

1. 공식 simulator와 policy adapter의 `check_block_color` 과업에서 `info_complete`, 색 판정, target mask, subtask, 성공 predicate의 생성·기록·policy 노출 범위를 확인한다. 공개 LeRobot shard가 숨은 색과 최종 성공을 실제로 포함하는지도 별도로 확인한다. Metadata나 demo의 정답을 정책 입력으로 잘못 간주하지 않는다.
2. Source 계약이 허용하면 official fixed ID evaluation seed의 앞 소수 사례를 고정하고 정상 정책 rollouts에서 색 단서의 실제 가시성, 선택 pad와 최종 성공을 독립 판독한다. 한 사례라도 정보 획득과 목표 선택을 분리할 수 있으면 그 같은 초기 상태에서 허용된 과거 단서와 oracle target/subtask 대조를 시도한다. 초기 상태·개입 전 행동과 예산을 검산한다.
3. 한 과업의 구분 가능한 사례가 없거나 source/annotation·state restoration이 같은 상태 대조를 허용하지 않으면 그 사유를 기록하고 이 route의 투자 가치를 재판단한다. 무효한 대조를 성공률로 발표하지 않는다.

초기 비용 상한은 약 2 working days, 단일 RTX 5090의 소수 episode다. 전체 76.6 GB 자료와 공식 모델의 3개 checkpoint는 받지 않는다. 한 task의 파일/한 checkpoint도 필요한 경우에만 선택적으로 취득하며 크기·hash를 확인한다. 짧은 source/schema 조사 뒤 모델·simulator의 준비 비용이 관찰 가치보다 커지면 한 task의 작은 data/constructed 관찰로 전환할 수 있으나, 전환 이유와 해석 범위를 이 파일에 기록한다.

## Current Findings And Decision

The pinned simulator sets `info_complete` in `enter_rotate_action_stage()` rather than testing whether hidden color was read from pixels. `check_block_color` samples the ground-truth target in `load_actors()`; fixed-seed entries carry it in an `info` placeholder for instruction generation. The released policy configs use `instruction_type: unseen`, which does not reveal the target color in the audited templates. The online adapter tries environment subtask maps; actual runtime text exposure requires a rollout check and cannot be inferred from the training metadata alone. This is a source-level contract observation, not a model rollout result.

The released **training** LeRobot metadata shows a different contract: all 100/100 `task_instruction` fields and at least one subtask sentence per episode name the correct target color; `meta/tasks.jsonl` lists six color-specific tasks. A language-only target rule therefore covers these training labels without using the visual clue. In the official fixed ID and OOD seed lists, the first 50 seeds per split yield 200/250 `seen` instructions revealing the color and 0/250 `unseen` instructions revealing it, using whole-word matching. This is an instruction-contract comparison on the **same fixed seeds**, not a policy success result or proof of evaluation leakage. The three selected Parquet episodes have 246/179/190 rows with RGB/state/action/stage fields, but no `info_complete`, target mask or independent final outcome. At manually inspected green (episode 0) and red (episode 2) trajectories, the back-side color is visible during inspection and not in the chosen later decision frame. These are expert demonstrations, not learned-policy decisions. No policy error, target-choice error or method gain has been observed. The paper's `Context Retained` category is not an evidence-availability label.

### Limited Offline Policy Probe

The data-contract audit makes a training-row target-choice test invalid for visual-evidence attribution. The next bounded probe therefore holds each expert demonstration's **current** image/state fixed immediately before pad search (`subtask=4, stage=2`) and compares one released policy's action prediction under (a) generic `unseen`-style task text with full causal 16-step history and no subtask hint, (b) the same generic text with current-only input, (c) explicit training task text with full history, and (d) generic task text plus explicit color-bearing training subtask text with full history. The last condition is an oracle text upper bound, not the online evaluation input. This is a sensitivity and imitation-error diagnostic. Current-only input also changes sequence length and removes non-color history; a difference cannot be attributed solely to color. Expert data do not provide independent target-choice or execution labels, so this probe cannot establish a causal error breakdown or rollout success.

Interpretation fixed before viewing policy output: if the generic full-history condition lowers expert-prefix error in both selected colors, history may help action imitation, but color-specific use still requires an isolated evidence intervention and rollout. If only explicit target text improves agreement, examine instruction dependence and train/eval mismatch before proposing a memory method. If neither condition has a consistent action or error effect, do not enlarge this same offline comparison just to seek significance; re-evaluate the official two-seed rollout or another task. Two expert trajectories and 18D action L1 values do not support an efficacy claim. Source inspection suggests the online adapter may fall back to task text when environment subtask maps are absent; this probe explicitly separates a no-subtask input from an oracle color-bearing subtask. The later held-out request text is recorded in the fixed-seed section; it does not establish server equivalence.
